# 당곡고 스탠바이미 화면

스탠바이미 두 대로 소식과 작품 체험을 운영하는 화면입니다. A 화면은 소식과 작품 소개를, B 화면은 작품 직접 체험을 맡습니다. 지금은 2단계(구글 설문 등록과 관리 화면)까지 만들었습니다. 2단계는 학교 구글 계정에 Apps Script를 설치해야 동작합니다([apps-script/SETUP.md](apps-script/SETUP.md)). 소식 문구는 아직 시험용 예시이고, 실제 운영 문구는 3단계에서 솔라 프로4가 작성합니다. 단계와 요구사항 대조는 [PLAN.md](PLAN.md)에 있습니다.

## 주소

## 스탠바이미에서 여는 방법

스탠바이미에는 카메라가 없어서 QR을 읽어 주소를 열 수 없습니다. 주소는 처음 한 번만 터치 화면 키보드로 입력하고, 브라우저의 즐겨찾기나 홈 화면 추가 기능으로 저장합니다. 두 대 모두 같은 역할 선택 주소 하나만 입력하면 됩니다. QR은 반대 방향으로 사용합니다. 스탠바이미 화면의 QR을 휴대폰으로 찍어 진단 요약을 받거나 시험 실행 페이지를 엽니다.

1. 웹 브라우저 앱을 실행하고 역할 선택 주소를 입력합니다.
2. A 화면이나 B 화면 버튼을 누릅니다. 다음부터는 역할 선택 주소만 열어도 5초 뒤 지난번에 고른 화면으로 이동합니다.
3. 브라우저 메뉴의 전체 화면을 사용하거나, 진단 정보의 「전체 화면」 버튼을 누릅니다.
4. 화면의 빈 곳을 한 번 누르면 진단 정보가 표시됩니다. 2분 동안 조작이 없으면 진단 정보는 저절로 닫힙니다.

## 결과 전달 방법

진단 정보의 '진단 요약' QR을 휴대폰 카메라로 찍으면 한 줄짜리 글자가 표시됩니다. A와 B 화면에서 각각 복사해 전달합니다. 진단 정보 화면을 사진으로 찍어 보내도 됩니다.

## 휴대폰으로 시험 실행하기 (예비 경로)

긴급 정지, 공지, B 원격 시연은 Apps Script 관리 화면에서 버튼으로 합니다. 이 방법은 관리 화면을 사용할 수 없을 때의 예비 경로입니다. 두 방법 모두 `projects/control.json`을 바꾸고, 편성 스크립트가 이를 화면 내용에 합칩니다.

1. 휴대폰 브라우저로 시험 실행 주소를 엽니다. 진단 정보의 '휴대폰으로 시험 실행' QR을 찍어도 같은 페이지가 열립니다.
2. 「화면 배포」 페이지에서 Run workflow를 누릅니다.
3. 화면 상태, 공지 문구, 원격 시연(작품 번호나 id, 또는 주소)을 입력하고 실행합니다.

공지 문구나 원격 시연을 비워 두고 실행하면 해당 기능이 꺼집니다. 화면 배포는 작품 검사를 기다리지 않습니다. 작품을 모두 다시 검사하려면 Actions의 「작품 검사」를 '모든 작품을 다시 검사'로 실행합니다. 화면은 30초마다 새 내용을 확인합니다. 반영 지연에는 Actions 실행 시간, Pages 배포 시간, 캐시 시간, 최대 30초의 확인 간격이 모두 포함됩니다.

## 작품 등록과 편성

학생 작품은 구글 설문으로 받습니다([apps-script/SETUP.md](apps-script/SETUP.md)). 관리 시트가 [projects/registry.json](projects/registry.json)의 `source: form` 항목을 쓰고, 사람이 등록부에 직접 적은 항목(`source` 없음)은 그대로 둡니다. 학생 이메일은 등록부에 올라가지 않습니다.

| 항목 | 필수 | 뜻 |
|---|---|---|
| `id` | 필수 | 영문 소문자와 `-`로 된 작품 이름 |
| `title` | 필수 | 작품명 |
| `url` | 필수 | 실행 주소 |
| `summary` | 필수 | 한 줄 소개 (핵심 기능) |
| `maker` | 필수 | 제작자 표시명 |
| `makerType` | 선택 | 작품 카드 배지. `teacher` 선생님, `g1`·`g2`·`g3` 1·2·3학년. 설문의 '제작자 구분' 문항에서 옵니다. |
| `target` | 필수 | `wide` 큰 화면용, `mobile` 휴대폰용, `both` 둘 다 |
| `tryUrl` | 선택 | 체험 전용 주소 |
| `pinnedUrl` | 선택 | 버전이 고정된 주소 (예: Vercel 배포별 주소) |
| `howTo` | 선택 | 체험 방법 |
| `demoSteps` | 선택 | 자동 시연할 동작 2~3개. 4단계에서 사용합니다. |
| `makerConfirmed` | 승인 | 제작자 확인 여부 |
| `teacher` | 승인 | `pending` 승인 전, `approved` 게시, `hidden` 숨김 |
| `approvedAt` | 승인 | 교사가 승인한 시각. 다시 승인하면 바뀝니다. |
| `pinUntil` | 승인 | 이 날짜까지 추천 작품으로 먼저 보여 줍니다. |
| `source` | 자동 | 관리 시트가 쓴 항목은 `form` |

등록부가 바뀌면(push) 워크플로 두 개가 나눠서 처리합니다.

1. **「화면 배포」** (빠른 경로, 1분 안팎): 편성 스크립트(`scripts/build_projects.py`)가 등록부, 검사 결과, 화면 제어(`projects/control.json`)를 합쳐 `site/content.json`을 만들고 배포합니다. 게시 조건은 제작자 확인, 교사 승인, 검사 실패 아님, 숨김 아님입니다. 게시 작품에는 짧은 주소 `/p/번호`를 만듭니다.
2. **「작품 검사」** (느린 경로): 새 작품이나 주소가 바뀐 작품을 검사합니다(`scripts/check_projects.py`). 접속(HTTP), 다른 사이트 안에서 실행 가능 여부(X-Frame-Options, CSP frame-ancestors), 빈 화면, 스크립트 오류를 확인하고 큰 화면과 휴대폰 화면을 캡처합니다. 끝나면 화면 배포를 다시 부릅니다. 평일 하루 세 번 오래된 검사 결과도 다시 검사합니다.

- **승인 버전**: 승인할 때의 화면 지문을 `projects/assigned.json`에 남깁니다. 그 뒤 작품이 바뀌면 검토 화면과 관리 화면에 '승인 뒤 바뀜'을 표시합니다. 다시 승인하면 새로 기록합니다.
- **주소 변경**: 주소가 바뀐 작품은 새 주소로 검사를 마칠 때까지 게시하지 않습니다.
- **숨김**: `hidden`으로 바꾼 작품은 다시 검사·편성해도 게시하지 않고, 짧은 주소도 지웁니다.
- **배포 완료 확인**: 등록부의 `syncId`와 화면 제어의 `requestId`가 배포된 `projects/index.json`, `content.json`에 나타나면 관리 시트가 요청을 '반영 완료'로 바꿉니다.

검토 화면(`?review`)에서 등록된 작품 전체의 검사 결과, 게시하지 않는 이유, A·B 화면 미리보기를 한꺼번에 봅니다.

## 작품 체험 규칙 (B 화면)

- 「체험 시작」을 누르면 작품을 4분 동안 유지합니다. 「시간 연장 +3분」으로 최대 15분까지 늘리고, 「끝내기」로 바로 끝냅니다.
- 체험하는 동안에는 다른 작품으로 넘어가지 않습니다. 원격 시연 요청도 체험이 끝날 때까지 기다립니다.
- 긴급 정지는 체험보다 항상 우선합니다.
- 작품 안을 터치한 기록은 이 페이지가 알 수 없습니다. 그래서 시간과 버튼으로만 체험을 관리합니다.
- 다른 사이트 안에서 실행할 수 없는 작품과 휴대폰용 작품은 큰 QR과 짧은 주소로 안내합니다.
- 작품이 20초 안에 열리지 않으면 휴대폰 안내를 띄웁니다. 시간이 다 되면 소식 화면으로 돌아옵니다.

## 급식과 AI 뉴스

- 급식: 화면이 나이스 급식식단정보(서울 B10 · 당곡고 7010073)를 직접 받습니다. 인증키는 쓰지 않습니다(공개 저장소라 키가 드러나고, 키 없이도 5일치를 받을 수 있습니다). 오늘 점심을 크게, 다음 급식일 메뉴를 작게 보여 주고 메뉴마다 음식 아이콘을 붙입니다. 나이스가 응답하지 않으면 마지막으로 받은 식단을 씁니다.
- AI 뉴스: 「AI 뉴스」 워크플로가 AI타임스·연합뉴스·전자신문·ZDNet Korea·한겨레·동아일보·경향신문의 RSS에서 기사 6건을 골라 소식 앞에 넣습니다. 기사마다 분야(AI 기술·사회·경제·과학·건강·문화·생활)를 붙이고 분야마다 가장 좋은 기사를 먼저 고릅니다. 새 모델 발표, 벤치마크, 새로 발견한 문제와 해결에 점수를 더 주고, 기업 매출·주가·투자 유치 같은 돈 이야기와 자극적인 기사는 뺍니다. 맨 앞 「오늘의 AI 뉴스」 카드가 전체를 보여 주고, B 화면 QR은 휴대폰용 목록(`site/news.html`)으로 연결됩니다. 화면에는 제목, 요약 첫 문장, 출처만 보이고 기사 전문은 언론사 사이트에서 읽습니다. 기준은 `scripts/fetch_news.py` 맨 위에 있습니다.

## 알아 둘 점

- 앱 코드(`app.js`, `style.css`)를 고치면 `app.js`의 `APP_VERSION`과 `content.json`의 `appVersion`을 같은 값으로 올립니다. 화면이 새 버전을 감지하고 스스로 새로 고칩니다.
- 공지에 `noticeUntil`, 소식 카드에 `until`을 넣으면 그 시각이 지난 뒤 화면에서 내립니다.
- 미리보기(`?preview`)와 검토 화면의 미리보기는 실행 기록을 남기지 않습니다.
- 실행 기록은 각 스탠바이미의 브라우저 저장소에 남습니다. 진단 정보의 「기록 지우기」로 지웁니다.
- 로컬에서 작품을 검사하려면 Playwright(파이썬)가 필요합니다. `python3 scripts/check_projects.py --all`
- Apps Script 흐름은 구글 서비스를 흉내 낸 모의 시험으로 확인합니다. `node apps-script/test/run_test.mjs <임시 폴더>`
