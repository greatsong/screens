# 당곡고 스탠바이미 화면

스탠바이미 두 대로 소식과 작품 체험을 운영하는 화면입니다. A 화면은 소식과 작품 소개를, B 화면은 작품 직접 체험을 맡습니다. 지금은 1단계(작품 등록 MVP)까지 만들었습니다. 소식 문구는 아직 시험용 예시이고, 실제 운영 문구는 3단계에서 솔라 프로4가 작성합니다. 단계와 요구사항 대조는 [PLAN.md](PLAN.md)에 있습니다.

## 주소

| 화면 | 주소 |
|---|---|
| 역할 선택 (스탠바이미에 입력할 주소) | `greatsong.github.io/screens` |
| A 화면 (소식, 작품 소개) | https://greatsong.github.io/screens/?screen=a |
| B 화면 (깊이 보기, 작품 체험) | https://greatsong.github.io/screens/?screen=b |
| 두 화면 미리보기 (PC용) | https://greatsong.github.io/screens/?preview |
| 작품 검토 (PC용) | https://greatsong.github.io/screens/?review |
| 작품 짧은 주소 | `greatsong.github.io/screens/p/번호` |
| 시험 실행 (휴대폰용) | https://github.com/greatsong/screens/actions/workflows/pages.yml |

## 스탠바이미에서 여는 방법

스탠바이미에는 카메라가 없어서 QR을 읽어 주소를 열 수 없습니다. 주소는 처음 한 번만 터치 화면 키보드로 입력하고, 브라우저의 즐겨찾기나 홈 화면 추가 기능으로 저장합니다. 두 대 모두 같은 역할 선택 주소 하나만 입력하면 됩니다. QR은 반대 방향으로 사용합니다. 스탠바이미 화면의 QR을 휴대폰으로 찍어 진단 요약을 받거나 시험 실행 페이지를 엽니다.

1. 웹 브라우저 앱을 실행하고 역할 선택 주소를 입력합니다.
2. A 화면이나 B 화면 버튼을 누릅니다. 다음부터는 역할 선택 주소만 열어도 5초 뒤 지난번에 고른 화면으로 이동합니다.
3. 브라우저 메뉴의 전체 화면을 사용하거나, 진단 정보의 「전체 화면」 버튼을 누릅니다.
4. 화면의 빈 곳을 한 번 누르면 진단 정보가 표시됩니다. 2분 동안 조작이 없으면 진단 정보는 저절로 닫힙니다.

## 점검표 (실기기)

| 번호 | 확인할 것 | 방법 | 진단 정보에서 볼 곳 |
|---|---|---|---|
| 1 | 전체 화면 유지 | 전체 화면으로 바꾼 뒤 10분 동안 둡니다. | 전체 화면 |
| 2 | 터치 | 화면을 손가락으로 누릅니다. | 터치 입력 |
| 3 | 두 화면 동기 | 두 대를 나란히 두고 카드가 바뀌는 순간을 비교합니다. | 시계 보정, 기기 정보의 카드 |
| 4 | 반영 지연 | 아래 「휴대폰으로 시험 실행하기」로 공지 문구를 넣습니다. 공지가 표시될 때까지 기다립니다. | 반영 지연 |
| 5 | 긴급 정지 | 같은 방법으로 화면 상태를 `stop`으로 실행합니다. B 화면에서 작품을 체험하는 중에 실행해서 정지 화면이 작품보다 앞에 나오는지 봅니다. | 최근 기록 |
| 6 | 전원 복귀 | 리모컨으로 전원을 끄고 켭니다. 브라우저가 이 페이지로 돌아오는지 봅니다. | 이전 실행, 실행 기록 |
| 7 | 자동 꺼짐 | 아침에 켜 두고 손대지 않은 채 오후에 확인합니다. 화면이 실제로 켜져 있었는지는 직접 봅니다. | 연속 표시(끊김 없이 4시간), 이전 실행(4시간 자동 꺼짐 의심 표시) |
| 8 | 학교 무선망 | 학교 무선망으로 접속합니다. 기기 등록이 필요한지 확인합니다. | 콘텐츠 확인 |
| 9 | 작품 체험 | B 화면의 「작품 체험하기」나 작품 카드의 「체험 시작」을 누릅니다. 남은 시간, 「시간 연장 +3분」, 「끝내기」, 「휴대폰으로 이어서」를 확인합니다. 그림판은 여러 손가락으로 그리고, Commit Galaxy는 3D 그래픽이 끊기지 않는지 봅니다. | 최근 기록 |
| 10 | 원격 시연 | 「휴대폰으로 시험 실행하기」에서 원격 시연에 작품 번호(예: `2`)를 넣고 실행합니다. B 화면에는 작품이, A 화면에는 시연 안내가 표시되는지 봅니다. 학생이 체험하는 중이면 체험이 끝난 뒤 열립니다. | 최근 기록 |
| 11 | 노트북·태블릿 미러링 | 윈도 노트북은 Win+K(Miracast), 아이패드와 맥은 AirPlay로 공유합니다. 크롬북은 기본 기능으로 연결되지 않을 수 있습니다. 공유를 끝낸 뒤 브라우저 화면으로 돌아오는지 봅니다. | 최근 기록의 '화면이 가려짐', '화면이 다시 보임' |
| 12 | 맥미니 AirPlay | 맥미니에서 스탠바이미 한 대로 AirPlay를 연결합니다. 연결한 채로 다른 한 대에도 따로 연결할 수 있는지, 끝낸 뒤 브라우저로 돌아오는지 봅니다. | 최근 기록 |
| 13 | 맥미니 학교망 접속 | 맥미니에서 `python3 -m http.server 8000`을 실행하고, 스탠바이미 브라우저로 `http://맥미니IP:8000`을 엽니다. 열리면 맥미니를 상태 서버로 쓸 수 있습니다. | 없음 |
| 14 | 가독성과 QR | 2~3m 떨어져 글자를 읽고, 휴대폰으로 화면의 QR을 인식합니다. | 없음 |

미러링 지원 방식은 기종과 펌웨어에 따라 다르므로 현장에서 확인합니다.

## 결과 전달 방법

진단 정보의 '진단 요약' QR을 휴대폰 카메라로 찍으면 한 줄짜리 글자가 표시됩니다. A와 B 화면에서 각각 복사해 전달합니다. 진단 정보 화면을 사진으로 찍어 보내도 됩니다.

## 휴대폰으로 시험 실행하기

1. 휴대폰 브라우저로 시험 실행 주소를 엽니다. 진단 정보의 '휴대폰으로 시험 실행' QR을 찍어도 같은 페이지가 열립니다.
2. 「화면 배포」 페이지에서 Run workflow를 누릅니다.
3. 화면 상태, 공지 문구, 원격 시연(작품 번호나 id, 또는 주소)을 입력하고 실행합니다.

공지 문구나 원격 시연을 비워 두고 실행하면 해당 기능이 꺼집니다. 수동 실행은 빠르게 반영되도록 작품 검사를 건너뜁니다. 작품을 모두 다시 검사하려면 '작품 검사도 함께 실행'을 켭니다. 화면은 30초마다 새 내용을 확인합니다. 반영 지연에는 Actions 실행 시간, Pages 배포 시간, 캐시 시간, 최대 30초의 확인 간격이 모두 포함됩니다.

## 작품 등록과 편성

작품은 [projects/registry.json](projects/registry.json)에 등록합니다. 2단계에서 등록 양식과 관리 화면 버튼으로 바꿉니다.

| 항목 | 필수 | 뜻 |
|---|---|---|
| `id` | 필수 | 영문 소문자와 `-`로 된 작품 이름 |
| `title` | 필수 | 작품명 |
| `url` | 필수 | 실행 주소 |
| `summary` | 필수 | 한 줄 소개 (핵심 기능) |
| `maker` | 필수 | 제작자 표시명 |
| `target` | 필수 | `wide` 큰 화면용, `mobile` 휴대폰용, `both` 둘 다 |
| `tryUrl` | 선택 | 체험 전용 주소 |
| `pinnedUrl` | 선택 | 버전이 고정된 주소 (예: Vercel 배포별 주소) |
| `howTo` | 선택 | 체험 방법 |
| `demoSteps` | 선택 | 자동 시연할 동작 2~3개. 4단계에서 사용합니다. |
| `makerConfirmed` | 승인 | 제작자 확인 여부 |
| `teacher` | 승인 | `pending` 승인 전, `approved` 게시, `hidden` 숨김 |
| `pinUntil` | 승인 | 이 날짜까지 추천 작품으로 먼저 보여 줍니다. |

등록부가 바뀌면(push) 다음 순서로 자동 처리합니다. 평일 하루 세 번 정기 실행에서도 오래된 검사 결과를 다시 검사합니다.

1. **검사** (`scripts/check_projects.py`): 접속(HTTP), 다른 사이트 안에서 실행 가능 여부(X-Frame-Options, CSP frame-ancestors), 빈 화면, 스크립트 오류를 확인합니다. 큰 화면과 휴대폰 화면을 캡처합니다.
2. **편성** (`scripts/build_projects.py`): 제작자 확인과 교사 승인을 모두 받고, 검사에 실패하지 않은 작품만 게시합니다. 게시 작품에는 짧은 주소 `/p/번호`를 만듭니다.
3. **승인 버전**: 승인된 작품은 처음 편성할 때의 화면 지문을 등록부에 남깁니다. 그 뒤 작품이 바뀌면 검토 화면에 '승인 뒤 작품이 바뀜'을 표시합니다.
4. **숨김**: `hidden`으로 바꾼 작품은 다시 검사·편성해도 게시하지 않고, 짧은 주소도 지웁니다.

검토 화면(`?review`)에서 등록된 작품 전체의 검사 결과, 게시하지 않는 이유, A·B 화면 미리보기를 한꺼번에 봅니다.

## 작품 체험 규칙 (B 화면)

- 「체험 시작」을 누르면 작품을 4분 동안 유지합니다. 「시간 연장 +3분」으로 최대 15분까지 늘리고, 「끝내기」로 바로 끝냅니다.
- 체험하는 동안에는 다른 작품으로 넘어가지 않습니다. 원격 시연 요청도 체험이 끝날 때까지 기다립니다.
- 긴급 정지는 체험보다 항상 우선합니다.
- 작품 안을 터치한 기록은 이 페이지가 알 수 없습니다. 그래서 시간과 버튼으로만 체험을 관리합니다.
- 다른 사이트 안에서 실행할 수 없는 작품과 휴대폰용 작품은 큰 QR과 짧은 주소로 안내합니다.
- 작품이 20초 안에 열리지 않으면 휴대폰 안내를 띄웁니다. 시간이 다 되면 소식 화면으로 돌아옵니다.

## 파일 구성

| 파일 | 하는 일 |
|---|---|
| `site/index.html`, `site/app.js`, `site/style.css` | 화면 |
| `site/content.json` | 화면 내용. 작품 편성은 편성 스크립트가 채웁니다. |
| `site/projects/` | 작품별 검사 결과와 캡처, 검토 화면용 `index.json` |
| `site/p/` | 작품 짧은 주소 |
| `site/demo/touch.html` | 동시 터치 확인용 그림판 |
| `projects/registry.json` | 작품 등록부 |
| `scripts/check_projects.py` | 작품 검사와 캡처 |
| `scripts/build_projects.py` | 작품 편성 |
| `scripts/bump.py` | 수동 실행 때 버전, 게시 시각, 상태, 공지, 원격 시연을 바꿉니다. |
| `.github/workflows/pages.yml` | 검사, 편성, 배포, 수동 실행 |

## 알아 둘 점

- 앱 코드(`app.js`, `style.css`)를 고치면 `app.js`의 `APP_VERSION`과 `content.json`의 `appVersion`을 같은 값으로 올립니다. 화면이 새 버전을 감지하고 스스로 새로 고칩니다.
- 공지에 `noticeUntil`, 소식 카드에 `until`을 넣으면 그 시각이 지난 뒤 화면에서 내립니다.
- 미리보기(`?preview`)와 검토 화면의 미리보기는 실행 기록을 남기지 않습니다.
- 실행 기록은 각 스탠바이미의 브라우저 저장소에 남습니다. 진단 정보의 「기록 지우기」로 지웁니다.
- 로컬에서 작품을 검사하려면 Playwright(파이썬)가 필요합니다. `python3 scripts/check_projects.py --all`
