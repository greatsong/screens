# 당곡고 스탠바이미 화면 시험

스탠바이미 두 대로 소식 화면을 운영하기 전에 기기 동작을 확인하는 시험 페이지입니다. 소식 자동 수집은 아직 없고, 화면 문구는 모두 시험용 예시입니다. 실제 운영 문구는 2단계에서 솔라 프로4가 작성합니다.

## 주소

| 화면 | 주소 |
|---|---|
| 역할 선택 (스탠바이미에 입력할 주소) | `greatsong.github.io/screens` |
| A 화면 (소식) | https://greatsong.github.io/screens/?screen=a |
| B 화면 (깊이 보기, 학생 작품 시연) | https://greatsong.github.io/screens/?screen=b |
| 두 화면 미리보기 (PC용) | https://greatsong.github.io/screens/?preview |
| 시험 실행 (휴대폰용) | https://github.com/greatsong/screens/actions/workflows/pages.yml |

## 스탠바이미에서 여는 방법

스탠바이미에는 카메라가 없어서 QR을 읽어 주소를 열 수 없습니다. 주소는 처음 한 번만 터치 화면 키보드로 입력하고, 브라우저의 즐겨찾기나 홈 화면 추가 기능으로 저장합니다. 두 대 모두 같은 역할 선택 주소 하나만 입력하면 됩니다. QR은 반대 방향으로 사용합니다. 스탠바이미 화면의 QR을 휴대폰으로 찍어 진단 요약을 받거나 시험 실행 페이지를 엽니다.

1. 웹 브라우저 앱을 실행하고 역할 선택 주소를 입력합니다.
2. A 화면이나 B 화면 버튼을 누릅니다. 다음부터는 역할 선택 주소만 열어도 5초 뒤 지난번에 고른 화면으로 이동합니다.
3. 브라우저 메뉴의 전체 화면을 사용하거나, 진단 정보의 「전체 화면」 버튼을 누릅니다.
4. 화면을 한 번 누르면 진단 정보가 표시됩니다. 2분 동안 조작이 없으면 진단 정보는 저절로 닫힙니다.

## 점검표

| 번호 | 확인할 것 | 방법 | 진단 정보에서 볼 곳 |
|---|---|---|---|
| 1 | 전체 화면 유지 | 전체 화면으로 바꾼 뒤 10분 동안 둡니다. | 전체 화면 |
| 2 | 터치 | 화면을 손가락으로 누릅니다. | 터치 입력 |
| 3 | 두 화면 동기 | 두 대를 나란히 두고 카드가 바뀌는 순간을 비교합니다. | 시계 보정, 기기 정보의 카드 |
| 4 | 반영 지연 | 아래 「휴대폰으로 시험 실행하기」로 공지 문구를 넣습니다. 공지가 표시될 때까지 기다립니다. | 반영 지연 |
| 5 | 긴급 정지 | 같은 방법으로 화면 상태를 `stop`으로 실행합니다. 시계 화면으로 바뀌면 다시 `normal`로 실행합니다. | 최근 기록 |
| 6 | 전원 복귀 | 리모컨으로 전원을 끄고 켭니다. 브라우저가 이 페이지로 돌아오는지 봅니다. | 이전 실행, 실행 기록 |
| 7 | 자동 꺼짐 | 아침에 켜 두고 손대지 않은 채 오후에 확인합니다. | 연속 실행(4시간을 넘기면 통과), 이전 실행(4시간 자동 꺼짐 의심 표시) |
| 8 | 학교 무선망 | 학교 무선망으로 접속합니다. 기기 등록이 필요한지 확인합니다. | 콘텐츠 확인 |
| 9 | 학생 작품 실행 | B 화면의 「학생 작품 시연」에서 샘플 세 개를 실행합니다. 그림판은 여러 손가락으로 그리고, Commit Galaxy는 3D 그래픽이 끊기지 않는지 봅니다. | 최근 기록 |
| 10 | 원격 시연 | 「휴대폰으로 시험 실행하기」에서 작품 주소를 넣고 실행합니다. B 화면에는 작품이, A 화면에는 시연 안내가 표시되는지 봅니다. | 최근 기록 |
| 11 | 미러링 | 노트북이나 태블릿 화면을 스탠바이미로 공유합니다. 윈도 노트북은 Win+K(Miracast), 아이패드와 맥은 AirPlay를 사용합니다. 크롬북은 기본 기능으로 연결되지 않을 수 있습니다. 공유를 끝낸 뒤 브라우저 화면으로 돌아오는지도 봅니다. | 최근 기록의 '화면이 가려짐', '화면이 다시 보임' |
| 12 | 가독성과 QR | 2~3m 떨어져 글자를 읽고, 휴대폰으로 B 화면의 QR을 인식합니다. | 없음 |

미러링 지원 방식은 기종과 펌웨어에 따라 다르므로 현장에서 확인합니다.

## 결과 전달 방법

진단 정보의 '진단 요약' QR을 휴대폰 카메라로 찍으면 한 줄짜리 글자가 표시됩니다. A와 B 화면에서 각각 복사해 전달합니다. 진단 정보 화면을 사진으로 찍어 보내도 됩니다.

## 휴대폰으로 시험 실행하기

1. 휴대폰 브라우저로 시험 실행 주소를 엽니다. 진단 정보의 '휴대폰으로 시험 실행' QR을 찍어도 같은 페이지가 열립니다.
2. 「화면 배포」 페이지에서 Run workflow를 누릅니다.
3. 화면 상태, 공지 문구, 원격 시연 주소를 입력하고 실행합니다.

공지 문구나 원격 시연 주소를 비워 두고 실행하면 해당 기능이 꺼집니다. 화면은 30초마다 새 내용을 확인합니다. 그래서 반영 지연에는 Actions 실행 시간, Pages 배포 시간, 캐시 시간, 최대 30초의 확인 간격이 모두 포함됩니다.

## 학생 작품 시연

- B 화면 아래의 「학생 작품 시연」 버튼을 누르면 작품 목록이 표시됩니다.
- 작품은 B 화면 안에서 실행되고, 5분이 지나면 소식 화면으로 돌아옵니다. 「+5분」 버튼으로 시간을 늘립니다.
- 작품 사이트가 다른 사이트 안에서 실행되는 것을 막아 두었으면 빈 화면이나 오류가 표시됩니다. 이때는 「새 창으로 열기」를 사용합니다.
- 작품 목록은 `site/content.json`의 `showcase.apps`에서 고칩니다. Streamlit 앱은 주소 끝에 `?embed=true`를 붙이면 화면에 맞게 표시됩니다.
- 작품 안을 터치한 기록은 이 페이지가 알 수 없습니다. 그래서 조작 여부와 관계없이 정해진 시간이 지나면 돌아옵니다.

## 파일 구성

| 파일 | 하는 일 |
|---|---|
| `site/index.html`, `site/app.js`, `site/style.css` | 화면 |
| `site/content.json` | 화면 내용. 2단계부터 자동으로 만듭니다. |
| `site/demo/touch.html` | 동시 터치 확인용 그림판 |
| `scripts/bump.py` | 시험 실행 때 버전, 게시 시각, 상태, 공지, 원격 시연을 바꿉니다. |
| `.github/workflows/pages.yml` | 배포와 시험 실행 |

## 알아 둘 점

- 앱 코드(`app.js`, `style.css`)를 고치면 `app.js`의 `APP_VERSION`과 `content.json`의 `appVersion`을 같은 값으로 올립니다. 화면이 새 버전을 감지하고 스스로 새로 고칩니다.
- 미리보기(`?preview`)는 실행 기록을 남기지 않습니다.
- 실행 기록은 각 스탠바이미의 브라우저 저장소에 남습니다. 진단 정보의 「기록 지우기」로 지웁니다.
