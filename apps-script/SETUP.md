# 작품 등록 설치 안내 (구글 설문 + Apps Script)

학생은 구글 설문으로 작품을 등록하고, 결과는 메일과 「내 작품 상태」 화면으로 받습니다. 학생에게 GitHub 계정은 필요 없습니다. 학생 이메일은 학교 구글 시트에만 남고, GitHub에는 작품명·제작자 표시명·소개·주소처럼 공개해도 되는 항목만 올라갑니다.

준비물은 두 가지입니다. 설문·시트·메일을 맡을 학교 구글 계정과, 토큰을 만들 GitHub `greatsong` 계정이 필요합니다. 처음 한 번 설치하는 데 20분쯤 걸립니다.

## 지금 설치 상태 (2026-10-30)

clasp로 프로젝트 만들기, 파일 올리기, 웹 앱 배포를 마쳤습니다. 남은 일은 토큰 만들기, 토큰 넣기, setup 실행입니다.

| 항목 | 상태 |
|---|---|
| Apps Script 프로젝트 | 개인 계정 `greatsong21@gmail.com`의 「당곡고 스탠바이미 작품 등록」 ([편집기](https://script.google.com/d/1e6LcTU-Z5If6BiCLsTd4nMDysxKu67lwUw8ox77UE4hW-Tp4uZ8_sFhg/edit)) |
| 올린 파일 | `Code.gs`, `Deploy.gs`, `Admin.html`, `Status.html`, `appsscript.json` |
| 학생용 상태 화면 | 배포함(누구나 링크로 열 수 있음). 주소는 `Deploy.gs`의 `STATUS_URL` |
| 관리 화면 | 테스트 배포(/dev) 주소. 스크립트 주인 계정으로 로그인해야 열림. 주소는 `Deploy.gs`의 `ADMIN_URL` |
| 등록 설문 | setup을 실행하면 만들어짐. 로그인 없이 제출하고 이메일 문항이 있음 |

개인 계정이라 메일은 하루 100통까지 보낼 수 있고, 학생 이메일은 이 계정의 관리 시트에 저장됩니다.

남은 순서는 다음과 같습니다.

1. [토큰 만들기 링크](https://github.com/settings/personal-access-tokens/new?name=screens-apps-script&description=%EB%8B%B9%EA%B3%A1%EA%B3%A0%20%EC%8A%A4%ED%83%A0%EB%B0%94%EC%9D%B4%EB%AF%B8%20Apps%20Script%EA%B0%80%20greatsong%2Fscreens%20%EB%93%B1%EB%A1%9D%EB%B6%80%EC%99%80%20%ED%99%94%EB%A9%B4%20%EC%A0%9C%EC%96%B4%20%ED%8C%8C%EC%9D%BC%EC%9D%84%20%EA%B3%A0%EC%B9%A0%20%EB%95%8C%20%EC%82%AC%EC%9A%A9&target_name=greatsong&expires_in=365&contents=write)를 엽니다. 이름, 설명, 만료(365일), Contents 쓰기 권한이 채워져 있습니다. Repository access에서 Only select repositories → `greatsong/screens`를 직접 고르고 Generate token을 누릅니다.
2. 편집기 왼쪽 「프로젝트 설정」 → 스크립트 속성에 `GITHUB_TOKEN`을 추가하고 토큰을 붙여 넣습니다.
3. 편집기에서 함수 `setup`을 고르고 실행합니다. 권한 요청을 승인합니다. '확인되지 않은 앱' 경고가 나오면 「고급」 → 「(안전하지 않음)으로 이동」을 누릅니다. 내 계정에서 내가 만든 스크립트라서 나오는 경고입니다.
4. 실행 기록에 표시되는 설문 주소를 학생에게 안내하고, `Deploy.gs`의 `ADMIN_URL`(관리 화면)을 휴대폰 홈 화면에 추가합니다.

코드를 고친 뒤에는 이 폴더에서 다음 두 명령으로 올리고 다시 배포합니다. 학생용 주소는 바뀌지 않습니다.

```bash
clasp push -f && clasp create-deployment -i AKfycbzB-wjnRBZgbcumLMfQlc3-EZVv7LXr-rKBPY5QzJSf63OKr4Xlc0-5SAL2iQnmo8fJuA -d "학생용 상태 화면"
```

아래 1~6단계는 처음부터 손으로 설치할 때의 안내입니다.

## 1단계. GitHub 토큰 만들기

1. github.com에서 Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token을 차례로 누릅니다.
2. 이름은 `screens-apps-script`, 만료는 1년으로 정합니다. 만료되기 전에 다시 만들어 3단계 값을 바꿉니다.
3. Repository access에서 Only select repositories를 고르고 `greatsong/screens`만 선택합니다.
4. Repository permissions에서 Contents를 Read and write로 바꿉니다. 나머지는 기본값으로 둡니다.
5. 만든 토큰은 한 번만 표시됩니다. 다른 곳에 저장하거나 공유하지 말고 3단계에 바로 붙여 넣습니다.

## 2단계. Apps Script 프로젝트 만들기

1. 학교 계정으로 script.google.com에 들어가 새 프로젝트를 만들고 이름을 「스탠바이미 작품 등록」으로 바꿉니다.
2. 왼쪽 「프로젝트 설정」에서 시간대가 서울(GMT+09:00)인지 확인하고, 「편집기에 appsscript.json 매니페스트 파일 표시」를 켭니다.
3. 이 폴더의 파일 네 개를 붙여 넣습니다.

| 이 폴더의 파일 | Apps Script에서 |
|---|---|
| `Code.gs` | 처음 있는 `Code.gs`의 내용을 모두 바꿉니다. |
| `Admin.html` | 파일 추가 → HTML, 이름 `Admin` |
| `Status.html` | 파일 추가 → HTML, 이름 `Status` |
| `appsscript.json` | 매니페스트 파일의 내용을 모두 바꿉니다. |

## 3단계. 스크립트 속성 넣기

「프로젝트 설정」 → 스크립트 속성에 다음 값을 추가합니다.

| 속성 | 값 | 필수 |
|---|---|---|
| `GITHUB_TOKEN` | 1단계에서 만든 토큰 | 필수 |
| `REQUIRE_SCHOOL_LOGIN` | 학교 워크스페이스 계정에 설치하고 학생에게 학교 계정이 있으면 `true`. 학교 계정으로 로그인해야 제출할 수 있습니다. 넣지 않으면 로그인 없이 제출하고 설문에 이메일 문항이 생깁니다. | 선택 |
| `ADMIN_EMAILS` | 관리 화면을 함께 사용할 선생님 이메일 (쉼표로 구분) | 선택 |

`WEBAPP_URL`은 5단계에서 넣습니다.

## 4단계. setup 실행

1. 편집기 위쪽 함수 목록에서 `setup`을 고르고 실행합니다.
2. 권한 요청이 나오면 승인합니다. 설문·시트를 만들고, 메일을 보내고, GitHub와 통신하는 권한입니다.
3. 실행 기록에 설문 주소와 관리 시트 주소가 표시됩니다.

setup이 하는 일은 세 가지입니다.
- 관리 시트를 만들고 '작품', '요청' 탭을 준비합니다.
- 등록 설문을 만듭니다.
- 자동 실행 시각을 설치합니다. 설문 제출 즉시, 평일 7시 30분·12시·15시 30분 무렵 정기 동기화, 10분마다 결과 확인(7시~19시)입니다.

등록 설문 문항은 작품명, 실행 주소, 한 줄 소개, 제작자 표시명, 어느 화면에 맞나요, 체험 방법, 체험 전용 주소, 자동 시연할 동작, 공개 동의입니다. 학교 계정 로그인을 끄면 결과를 받을 이메일 문항이 추가됩니다. 설문은 제출 뒤에도 고칠 수 있게 설정됩니다.

## 5단계. 웹 앱 배포

1. 오른쪽 위 배포 → 새 배포 → 유형 선택에서 웹 앱을 고릅니다.
2. 실행 사용자는 「나」로 둡니다.
3. 액세스 권한은 학생에게 학교 구글 계정이 있으면 학교 도메인 사용자로, 없으면 「모든 사용자」로 정합니다.
4. 배포한 뒤 표시되는 웹 앱 주소(`…/exec`로 끝남)를 스크립트 속성 `WEBAPP_URL`에 넣습니다.
5. 관리 화면은 웹 앱 주소 뒤에 `?page=admin`을 붙인 주소입니다. 휴대폰 홈 화면에 추가해 둡니다.

관리 화면은 스크립트를 만든 계정과 `ADMIN_EMAILS`에 넣은 계정만 열 수 있습니다. 학생이 관리 기능을 직접 불러도 서버에서 막습니다. 코드를 고친 뒤에는 배포 관리 → 수정 → 새 버전으로 다시 배포합니다. 주소는 그대로 유지됩니다.

## 6단계. 확인

1. 학생 계정이나 본인 계정으로 설문을 한 번 제출합니다. 접수 메일이 오는지 봅니다.
2. 관리 화면에서 작품이 '접수'로 보이는지 확인하고 「지금 반영」을 누릅니다.
3. 몇 분 뒤 '확인 요청' 메일이 오는지 봅니다. 메일의 「화면 확인하기」로 캡처와 A·B 미리보기를 확인합니다.
4. 「확인했습니다」를 누르면 교사에게 검토 알림 메일이 옵니다. 관리 화면에서 「게시 승인」을 누릅니다.

## 결과 전달 방법

결과는 학교 구글 메일과 「내 작품 상태」 화면 두 가지로 전달합니다.

| 시점 | 받는 사람 | 방법 | 내용 |
|---|---|---|---|
| 제출 직후 | 제작자 | 메일 | 접수 확인, 다음 처리 시각, 상태 화면 링크, 작품 정보 고치기 링크 |
| 입력 오류 (https 아님 등) | 제작자 | 메일 | 고칠 점 |
| 자동 검사 실패 | 제작자 | 메일 | 문제 목록, 고치기 링크. 교사에게는 보내지 않습니다. |
| 자동 검사 통과 | 제작자 | 메일 + 상태 화면 | 캡처, A·B 화면 미리보기, 「확인했습니다」 버튼 |
| 제작자 확인 뒤 | 교사 | 메일 한 통으로 묶음 | 검토할 작품 목록, 관리 화면 링크 |
| 교사 수정 요청 | 제작자 | 메일 | 교사가 적은 요청 문구, 고치기 링크 |
| 게시 시작 | 제작자 | 메일 | 휴대폰 체험 짧은 주소 |
| 승인 뒤 작품 변경 감지 | 제작자, 교사 | 메일 | 바뀐 사실. 교사가 관리 화면에서 다시 승인합니다. |

이 방식을 권하는 이유는 다음과 같습니다.
- 학생에게 GitHub 계정이 없어도 됩니다. 결과는 설문에 적은 이메일로 보냅니다. 학교 계정 로그인을 켜면 로그인한 이메일로 보냅니다.
- 실패와 보완은 제작자에게 먼저 갑니다. 교사는 제작자가 확인을 마친 작품만, 그것도 한 통으로 묶어 받습니다.
- 상태 화면은 메일의 링크로만 열립니다. 링크마다 따로 만든 열쇠가 들어 있어 다른 학생의 작품 상태는 볼 수 없습니다.
- 같은 결과로는 메일을 다시 보내지 않습니다.

검토했지만 쓰지 않은 방법도 있습니다. 클래스룸 공지는 학생마다 다른 결과를 따로 전하기 어렵습니다. 설문의 응답 수정 화면만으로는 검사 상태를 보여 줄 수 없습니다. 메신저는 학교 계정과 묶이지 않아 개인정보 관리가 어렵습니다.

## 운영 규칙

| 조작 | 반영 시점 |
|---|---|
| 설문 제출, 작품 정보 고치기, 제작자 확인, 게시 승인, 기간 고정, 보류 해제 | 다음 정기 동기화 (평일 하루 세 번). 관리 화면의 「지금 반영」으로 바로 보낼 수 있습니다. |
| 긴급 정지·해제, 공지, B 화면 실행·복귀 | 바로 (보통 1~2분) |
| 숨김 | 바로. 해당 작품만 내리고 다른 작품의 대기 중인 변경은 건드리지 않습니다. |

- 고쳐 제출한 작품은 제작자 확인과 교사 승인을 다시 거칩니다. 숨긴 작품은 고쳐 제출해도 숨김 상태로 남습니다.
- 보류한 작품은 보류를 풀 때까지 바뀐 내용을 GitHub에 보내지 않습니다.
- 요청 상태는 관리 시트의 '요청' 탭과 관리 화면 아래쪽에 표시됩니다. 접수 → 처리 중 → 반영 완료 순서로 바뀌고, 보류한 요청은 보류로 남습니다. '반영 완료'는 GitHub Pages에 배포된 것을 확인했다는 뜻입니다. 각 스탠바이미가 받았는지는 화면의 진단 정보로 확인합니다.
- 메일과 설문 문구는 `Code.gs`의 `TEXT` 한곳에 모여 있습니다.
- 메일 발송 한도는 학교 계정 기준 하루 1,500통입니다.

## 문제가 생기면

| 증상 | 확인할 곳 |
|---|---|
| 접수 메일이 오지 않음 | Apps Script → 실행 기록에서 `onFormSubmitTrigger` 오류 |
| 정기 동기화가 안 됨 | 실행 기록의 `scheduledSync`. 'GITHUB_TOKEN이 없습니다'나 '쓰기 실패 (401)'이면 토큰을 확인합니다. |
| 확인 요청 메일이 늦음 | GitHub → Actions의 「작품 검사」 실행 기록. 검사 준비에 1~2분 걸립니다. |
| 관리 화면이 '권한 없음' | 스크립트를 만든 학교 계정으로 로그인했는지 확인합니다. |
